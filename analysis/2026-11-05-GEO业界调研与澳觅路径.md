## 三、业界通用做法（学术 + 海外头部 + 国内竞品三角交叉）

### 3.1 学术实证：GEO 论文（这个词的源头）

【一手，WebFetch 抓取 arxiv.org/html/2311.09735v3 全文】Aggarwal et al., "GEO: Generative Engine Optimization", **KDD 2024**。GEO-bench 基准，9 种方法实测，核心结论：

| 方法 | 效果（Position-Adjusted Word Count，基线 19.3） |
|---|---|
| **Quotation Addition（加专家/权威言论引用）** | **27.8，+41% —— 最强** |
| Statistics Addition（加统计数据） | 25.9 |
| Fluency Optimization（流畅性优化） | 25.1 |
| Cite Sources（加来源引用） | 24.9 |
| Technical Terms | 23.1 |
| Easy-to-Understand | 22.2 |
| Authoritative（权威语气） | 21.8（主观印象指标上 22.9 尚可） |
| Unique Words | 20.7（几乎无效） |
| **Keyword Stuffing（关键词堆砌，传统 SEO 惯用）** | **17.8，低于基线 = 负效果**；Perplexity 真实引擎上比基线差 10% |

- 组合优于单一：Fluency + Statistics 组合比任何单一策略高 5.5%（§5.3）
- 真实引擎（Perplexity.ai）验证：Quotation +22%、Statistics +37%（§6, Table 5）
- **反直觉发现（Table 2）**：对搜索引擎排名第 5 的网站，Cite Sources 带来 +115.1% 可见性提升；**对已排第 1 的网站反而 -30.3%** ——优化方法的收益取决于你现在的位置
- 领域依赖（Table 3）：Cite Sources 对事实/陈述类查询和 Law&Gov 最有效；Fluency 对 Business/Science/Health 最有效；Statistics 对 Law&Gov/观点类最有效
- 摘要原文：整体「can boost visibility by up to 40%」

### 3.2 海外头部工具：Profound

【一手，WebFetch 抓取 tryprofound.com】
- 监测引擎：ChatGPT、Perplexity、Claude、Gemini、Microsoft Copilot、DeepSeek、Google AI Overviews
- 功能：Answer Engine Insights、Citation Analytics、**FactCheck（验证 AI 声明准确性）**、Shopping（SKU 级）、Agent Analytics（AI 爬虫如何看你的网站）、Sentiment、Context Manager
- **AI Marketer 智能体**：「identifies the work worth doing, drafts it, and pings you for approval」——AI 起草 + **人工审批**，场景包括：自动重写引用衰退的页面、为未覆盖问题新建页面、长文转社媒帖+配图、**追溯发布错误信息的媒体并起草更正邮件**
- 未披露定价（Get a Demo 模式）

### 3.3 三角交叉：业界通用做法 = 四层闭环

| 层 | 通用做法 | 论文/Profound | AnswerBit | InsGEO | 我们 |
|---|---|---|---|---|---|
| **测量** | 固定题库 × 多 AI 平台每日采集 → 提及率/排位/引用源 | —（论文是内容侧） | ✅ + 合成分数 | ✅ 8平台（1个是模拟） | ✅ 豆包单平台，数据可溯源 |
| **内容** | 加统计/加引用/加言论、结构化、FAQ；**禁关键词堆砌**；AI 生成 + 人工审批 | ✅ 实证 | ✅ AI 文章生成 | ✅ 智能创作（8篇） | ⚠️ spec §4.9 已设计未实现 |
| **分发** | 发到「被 AI 高引的平台」；App 商店描述；官网对 AI 爬虫友好；权威名录 | Agent Analytics 佐证 | ✅ 平台推荐+回填 | ✅ + **软文发稿市场（灰产面）** | ⚠️ 平台推荐已有，发布靠人工（spec 原设计） |
| **防守** | 事实一致性监测、错误更正 | FactCheck + 更正邮件 | 情感分析 | 做了但数据自相矛盾 | ✅ factcheck 框架已有，T8 卡住 |

一句话总结业界通用做法：**监测题库×多平台采集 → 引用源分析定位「去哪发」 → 按实证方法生产内容（加统计/引用/言论，绝不堆关键词） → 人工审核 → 发布到高被引平台 → 回填链接追踪被引闭环 → 事实错误监测与更正。**

两家国内竞品的共同商业本质：把「测量层」做成 SaaS 卖积分/套餐；InsGEO 还直接卖发稿（450-1005 积分/篇的软文套餐）。**优化动作层（真正改变 AI 回答的部分）两家都只做了浅层工具，做得深的是海外的 Profound（AI Marketer + 人工审批 + 更正邮件）。**

## 四、澳觅的最优路径（强品牌路径，不是弱品牌通用模板）

**前提校准（本会话实证）**：澳觅在豆包 31 条 valid 回答中提及率 87%（27/31）、排第一 61%（19/31）；InsGEO 口径下在 DeepSeek 也是排名 1.0、可见度 60%。**澳觅是强势品牌**，论文 Table 2 的警告直接适用：对已排第一的位置，盲目堆「加来源」类优化可能负收益（-30.3%）。强品牌的 GEO 重心是**补短板 + 防守 + 权威源**，不是海量发文冲可见度。

按 ROI 排序：

1. **游客场景补短板（最大失地）**：Q07「澳门旅游必备APP」0/2 提及、Q09 门票 0/1。InsGEO 引用榜显示游客场景的信源主力是 Facebook(486)/Instagram(344)/旅游垂类（bento.travel、klook 在我们的数据里也有）。动作：App Store 描述重写（两边数据都证明 apps.apple.com 是头部信源，且零成本）＋ 游客视角内容（用论文最优方法：加统计+加引用+加言论）发搜狐/什么值得买/旅游垂类。
2. **事实防守（强品牌的命门）**：豆包说过错澳觅商户数、把澳觅和 mFood 混为一谈、写成 MacauMall。错误事实会被持续引用放大。动作：修 T8 → fact_claims 跑起来 → 确认的错误清单直接变成文章选题（spec §4.11 已设计此衔接）；学 Profound 的「更正」思路——错误信源若是第三方文章，可联系更正。
3. **权威信源加强**：我们 3 天数据里 gov.mo 系域名被引 26 次（第二大信源群）；论文证明 Cite Sources 对 Law&Gov/事实类查询最有效、AI 有权威源偏好。动作：争取政府/旅游局名录、行业奖项、授权名单——一篇软文换不来的位置。
4. **官网 AI 友好化**：aomi.mo 仅被引 3 次。动作：FAQ 页（对应 Q08 支付/Q14 注册等高频问法）、数据页（商户数/用户数等 fact_items 的规范出处）、schema.org 结构化标记；有条件时监测 AI 爬虫访问日志（Profound Agent Analytics 的平价替代）。
5. **多平台复制验证**：第二期接入 Kimi/千问/文心后，验证「澳觅强势」是否跨平台成立（InsGEO 的 DeepSeek 数据侧证成立，但口径存疑）。**Facebook/Instagram 的高引用权重提示：澳门场景不能只看内地 AI**——但发布阵地是否值得投入海外平台，等多平台数据进来再定（现在只有 InsGEO 一家的聚合数字，未独立复核）。

**明确不推荐：**
- 买软文发稿套餐（InsGEO 式）：论文证明低质内容+关键词堆砌负效果；「出稿95%/秒出/审核非常轻松」的套餐内容质量可想而知；且有污染品牌事实底的风险（我们自己的 factcheck 会先抓到）
- 追求合成分数（Prominence Score/品牌指数）：两家竞品都有，公式任意且口径漂移（InsGEO 首页 46.69% vs 接口 56.72 实锤）——spec 反目标已排除，维持
- 对已占第一的场景重复堆文：论文 Table 2 的负收益警告

## 五、「我们自己可以实现吗」——分层判定

| 层 | 判定 | 依据 |
|---|---|---|
| 监测系统 | ✅ **已经实现了** | 本项目 = 数据质量更干净的 AnswerBit/InsGEO（每个数字可溯源到 run，无 Mock、无合成分数）；多平台扩展路线已核实（Kimi/通义/文心官方 API 可直连，≤60 元/平台/月，见姊妹篇第二期） |
| 内容优化动作 | ✅ **可以自己实现** | 论文方法可直接写成生成器规则（spec §4.9 管道已设计）；Profound 证明「AI 生成+人工审批」是业界头部形态，我们的标红审核关卡比它更严（无出处事实不许发布） |
| 发布与分发 | ⚠️ **半自动可以自己实现，全自动受限** | 半自动（生成→人工发→回填）零风险已设计；官方 API 直发待调研二返回；野路子自动化有封号风险（第三期分档方案） |
| 不可替代部分 | ❌ 需要公司资源，不是技术问题 | 平台账号（搜狐号/什么值得买/头条号）、App Store 开发者账号、政府/旅游局名录关系、自动发布的风险决策 |
| 不建议自己实现 | ❌ | 软文发稿市场（灰产）、无 API 平台的浏览器自动化监测（元宝）——InsGEO 用 deepseek+hunyuan 冒充元宝就是反面教材（反目标 2） |

**对第一期文章生成器的直接增量（论文实证 → prompt 规则）：**
1. 每篇必须包含具体统计数字（Statistics Addition，+35%；我们独有优势：fact_items + 年刊/白皮书知识库就是可溯源的数字库）
2. 加入权威引用或真实用户/专家言论（Quotation Addition，+41%，最强方法）
3. 关键事实挂来源链接（Cite Sources——但注意：只用在短板场景冲排名，已第一的场景少动）
4. 流畅性优先、结构清晰（Fluency + Statistics 组合最优，+5.5%；Business/Health 领域 Fluency 最有效）
5. **禁止关键词堆砌**（负效果，写进生成器硬校验）
6. 游客场景（Q07/Q09）用 Quotation+Statistics 组合；对比题（Q12）用 Fluency+事实准确性
